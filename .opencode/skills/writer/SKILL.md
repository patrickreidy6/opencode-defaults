# Writer

Use automatically for correspondence the user will send to another person: emails, workplace messages, and personal messages. Routine assistant replies, READMEs, reports, specifications, implementation plans, and command/skill prompts do not trigger this skill.

For other prose, use it only when the user explicitly requests `writer` (for example, `@writer`). Apply the voice rules only to the requested correspondence or explicitly selected prose; re-evaluate scope when the task changes.

Infer audience and purpose from the request; ask only when the missing context would materially change the message.

## Reidy's voice

- Direct, practical, grounded, and candid. Sound like a busy, capable person who wants a useful outcome.
- Lead with the real issue, decision, or ask. Include context only when it changes the reader's understanding or next action.
- Use natural, short-to-medium sentences and concrete wording. Technical terms are welcome when they clarify, not when they merely sound impressive.
- Keep warmth understated and emotion controlled. Be confident when justified, without showmanship or excessive deference.
- Prefer tight paragraphs and ranked recommendations when ranking helps. Avoid long preambles, generic catch-all lists, corporate filler, and repeated conclusions.

## Match the situation

- **Email:** Brief but complete, with a clear ask. Professional and natural; skip fake warmth and long niceties.
- **Workplace messages:** Composed, credible, and tactfully direct. State the issue and practical implications without passive aggression.
- **Personal messages:** Honest and sincere without dramatizing or adding emotion the user did not express.

## Editing and delivery

- Preserve the user's meaning, factual claims, and intended commitments. Required templates, technical detail, and supplied style guides take precedence over voice and brevity. Don't invent personal details to make prose feel authentic.
- Produce a ready-to-use draft in the requested format. For a narrow edit, match the surrounding voice and keep the edit narrow.
- Complete the requested revision before returning it. Explain editorial choices only when useful or requested.

## Voice calibration

Prefer: "What is worth prioritizing here?"

Avoid: "I would be most grateful for any thoughts you might have on this matter."
